# Environment asset workflow

Stage V pipeline, verified with **Blender 4.5.10 LTS**, **Godot 4.7.2 Standard** and Forward+. See the [approved proposal](../development/plans/phase_7_stage_v_environment_art_plan.md) and [delivery report](../development/reports/stage_v_environment_art.md). The initial library is original project work; reference images were not used as textures or imported meshes.

## Files and authority

- `assets/environment/source/`: editable Blender models and the shared material-source `.blend`. Its `.gdignore` prevents automatic Blender import; Git still includes sources. Blender backup files are ignored.
- `assets/environment/exports/`: explicit GLB runtime inputs, with tracked `.glb.import` settings. These are authored runtime files, distinct from ignored game builds.
- `assets/environment/textures/`: two original shared 1024 px periodic PNG maps, generated by `build_materials.py` with seed 65021.
- `resources/materials/environment/`: six shared runtime StandardMaterial3D resources. Ordinary GLB reimport does not overwrite these resources.
- `scenes/environment/modules/` and `props/`: reusable Node3D visual wrappers, no physics/navigation or gameplay scripts.
- `assets/environment/asset_manifest.json`: source/export SHA-256 identities, imported dimensions, triangle counts, material slots, origins and provenance. It deliberately changes when you edit an asset; it is not an economy or mission ledger.
- `.godot/`: compiled imports, validation artifacts and isolated saves, all ignored by Git. No LFS, commit or publication was added by this stage.

## Scale, orientation and editing

Use Metric units, 1 Blender unit = 1 metre. Apply object rotation and scale, keep the asset at the documented origin and maintain UV0. Blender Z-up converts through glTF +Y-up; source +Y service/front faces Godot −Z. The pilot's asymmetric service plate verifies this convention. Imported mesh/root bases are identity; do not fix orientation by scaling or adding compensating rotations in a Godot wrapper.

Walls, cabinet and bin use a floor-centre origin. Beam and utility run start at x=0 and extend along +X. Dimensions refer to imported mesh bounds; the cabinet's front is 0.393 m deep and the utility assembly 0.182 m tall, rather than filling their entire nominal design envelope. UV cube projection uses a 2 m repeat. Inspect density/seams at gameplay distance when adding new forms.

Open an existing source in Blender, make a normal mesh/material-slot edit and save it. Models are editable meshes; generation scripts retain original construction parameters. Existing names and material slots form part of the import contract. Bevels/normals are applied in the first generated sources; vertices remain editable. The library does not require procedural regeneration for manual changes.

From the repository root in PowerShell:

```powershell
blender --background assets/environment/source/structures/industrial_wall_4m.blend --python tools/art_pipeline/export_asset.py -- --output assets/environment/exports/structures/industrial_wall_4m.glb
godot --headless --path . --editor --quit
python tools/art_pipeline/audit_assets.py --write-manifest
godot --headless --path . --script res://tests/asset_pipeline_test.gd
```

The exporter reads the source's `asset` collection, checks applied scale/rotation, positive transforms, UVs and material slots, and exports selected meshes only. No cameras, lights or animation are exported. Save source before a batch export. Review the manifest changes; do not use `--write-manifest` to hide an unexpected edit.

For a **new** library asset's first Godot import, configure shared material mapping, then reimport:

```powershell
godot --headless --path . --editor --quit
godot --headless --path . --script res://tools/art_pipeline/configure_imports.gd
godot --headless --path . --editor --quit
```

The configuration utility applies the same material-name → external `.tres` mapping as Advanced Import Settings, disables animation, generated LODs and importer name suffixes, and invalidates only these library assets' generated checksum files to force reimport. It never removes source data or the user's whole `.godot` folder. Ordinary source re-export retains these settings; rerunning the configuration utility is unnecessary unless settings need repair. Imported visuals must have no generated physics/nav nodes.

To validate inventory without modifying it:

```powershell
python tools/art_pipeline/audit_assets.py
```

For deliberate procedural creation, `build_asset.py --asset <id>` refuses an existing source. `--rebuild` explicitly regenerates that source and must not be used for routine export or after hand edits without reviewing what will be lost. For example:

```powershell
blender --background --factory-startup --python tools/art_pipeline/build_asset.py -- --asset industrial_wall_2m
```

`build_materials.py` similarly protects its existing editable material source unless explicitly rebuilt. `write_materials.py` is an explicit reset of shared Godot material resources; do not run it during ordinary reimport. It converts the Blender linear palette to Godot's sRGB color parameters. Without that conversion the initial material pass rendered too dark. Godot material roughness is calibrated separately from simple Blender previews. Changing a source material name requires updating its external remap.

## Inspection and integration

```powershell
godot --path . res://scenes/environment/asset_inspection.tscn
godot --path . res://scenes/levels/expanded_salvage_complex.tscn
godot --path . res://scenes/levels/expanded_salvage_complex_graybox.tscn
```

The inspection scene is presentation only. In the mission, click Deploy. The processed bay is inside the western building, near the sorting machine at (−18, 0, 3). Both normal mission and graybox use identical gameplay configuration/markers and the same physical structure. The graybox variant changes `art_enabled` on the presentation component; replay preserves the selected scene. Default startup still opens compact Asset Recovery.

Keep structural colliders and their transforms, masks, navigation inputs, cover/peek and gameplay markers unchanged. The art wrapper replaces three primitive visual children and adds visible details, floor markings and two non-shadowed task lights. All imported solid details fit the existing box envelopes within the tested 12 mm detail tolerance. The sorting machine remains an enclosed solid base: it does not imply bullets can pass below open legs.

Beam, column, utility assembly and bin remain available in the library/inspection scene. They were not scattered through the world simply to display every export. A placement that creates a new apparently solid obstruction outside accepted collision needs a separately reviewed structural change. No new collider, path rebake callback, loot source or AI hook belongs in a visual wrapper.

## QA and iteration

The pilot was edited in its `.blend`, exported to the same GLB and reimported. Both instances received the changed mesh fingerprint with retained material paths; restoring the source restored the original fingerprint. An isolated clean project containing only GLBs, their import settings, material resources and textures successfully imported all eight assets without Blender sources/tool scripts or the main import cache.

Automated checks cover source/export identity, UVs, supported material bindings, bounds, shared instances, visual-only imports, protected U file hashes, exact collider/marker/nav settings, visual-envelope containment, real blocked/clear shots, camera spring-arm clearance and spectator permissions. Existing suites cover physical navigation through the dressed mission, finite materials/equipment, settlement and restart. These checks complement manual inspection; they cannot judge convincing wear, proportions, material consistency or target visibility.

Before multiplying an asset: inspect front/back/culling, bevel normals, UV tiling, nonuniform scaling, repeated instances, material response, camera clipping, visual/physical cover correspondence and lighting on actors. Test a source edit and reimport, not only the initial export. Compare graybox and art with fixed cameras/resolution and matching simulation; report unavailable renderer metrics explicitly. Track every original source/GLB/import setting/material and UID, while leaving caches/backups/builds ignored.

Static batches use `scripts/presentation/environment_mesh_batch.gd`: a source GLB PackedScene plus authored transforms, resolved at readiness or source-change notification. Do not embed imported mesh arrays or rely on transient importer-generated ArrayMesh subresource paths. Repeated instances must share the live imported mesh. The adapter supplies no input, collision, frame loop, actor movement, accounting or random placement. Editing/exporting/reimporting a source follows the existing workflow above.

The processing guard passed a protected source-edit/reimport/restoration round trip. Final tests cover source-change rebuilds and sharing; an isolated project imported the GLBs and initialized all nineteen model batches without Blender sources or the original import cache. Use `world_population_test.gd` with the existing asset pipeline and physical expanded-world suites.
